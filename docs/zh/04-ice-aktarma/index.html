    导入¶

    MRC Tuner Studio 支持多种来源格式。通常 A2L 的结果最可靠，因为定义文件能 锁定标定图地址、尺寸与物理缩放。

    A2L / DAMOS¶

    最可靠的路径。 ASAM MCD-2 MC（A2L）是随 ECU 软件提供的标准描述文件。

    1. 先导入 ROM 并创建工程。
    2. 选择 项目 ▸ 导入 A2L，指定 .a2l、.dam 或 .damos 文件。
    3. 应用会把 A2L 中的地址解析到你的 ROM 上。

    从 A2L 获取的信息：

    A2L 结构 用途
    RECORD_LAYOUT 字节大小、字节序、有/无符号
    STD_AXIS、COM_AXIS、FIX_AXIS 坐标轴定义与轴缩放
    COMPU_METHOD 换算到物理值的系数
    ECU_ADDRESS 基地址提示

    基地址识别

    A2L 地址是相对 24 位或 32 位基地址给出的。应用会依次尝试常见 ECU 基 地址表（MED17、EDC17、ME7、Simos、RH850、MPC …），并选择与 ROM 尺寸 一致的那个。必要时可通过 视图 ▸ 数据宽度 与 字节序 手动修正。

    Intel HEX 与 Motorola S-record¶

    .hex、.s19、.s28、.s37 文件可直接打开。应用会解析记录地址、保留空洞 并把数据转换为字节数组。

    HEX 输出

    写入 Intel HEX 与 S-record 可通过 Lua API（writeIntelHex、 writeSRecord）完成。项目 ▸ 导出 ROM 只提供 .bin 与 .rom。

    原始转储¶

    .bin、.rom、.ori、.mpc 按字节读取。但原始转储中没有任何关于标定 图起止位置的信息。此时：

    1. 运行 其他 ▸ 自动发现标定图，或
    2. 导入 A2L 文件，或
    3. 已知地址时用 查找 ▸ 标定图 手动定义。

    自动发现属于推断，请逐一检查它找到的每一张标定图。

    WinOLS（.ols）¶

    .ols 是包含 ROM 数据的完整容器。导入会带入：

    • ROM 数据，
    • 标定图名称、描述、地址、尺寸、单元格大小与缩放，
    • 坐标轴定义及其真实断点值，
    • 车辆/发动机/ECU 元数据。

    含多个固件版本的 OLS 工程会被导入为包含全部版本的单个工程。

    项目 ▸ 导出 OLS 可把工程写回 .ols。

    KP 标定图包（.kp）¶

    KP 包只携带标定图定义，不含 ROM，因此导入前必须打开一个带 ROM 数据的 工程。应用会：

    • 在你的 ROM 中解析地址（对 Tricore 风格 0x80xxxxxx 与平铺偏移分别评分），
    • 剔除与工程中已有标定图重复的条目，
    • 按名称前缀把新标定图归入文件夹。

    旧版 4.x 包有时不保存尺寸；应用会按单元格数量反推列数 × 行数。

    TunerPro（.xdf）¶

    .xdf 定义文件可导入也可导出。

    VAG 容器（.frf、.sgo、.odx）¶

    支持 .frf、.sgo、.odx 及其 .zip 打包。加密内容需要额外的 32 字节 AES 密钥/IV 文件。

    CSV 与 JSON 标定图清单¶

    项目 ▸ 导入 CSV 标定图清单 可从清单文件批量定义地址；导出 则把清单写回。

    导入之后¶

    • 启用 其他 ▸ 导入后自动扫描，让每次导入后自动发现标定图。
    • 若缩放可疑，在标定图属性中修正系数与偏移 —— 显示值直接由它决定。
